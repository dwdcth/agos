# 理论-实现对应审计

> 目的：校正 `doc/0415-00记忆认知架构.md` 与当前 Rust 代码库之间的对应关系。本文只记录“代码和测试能证实什么”，并显式区分：
>
> - `✅ 已实现`：默认或受支持运行路径上已接通，且有代码/测试证据
> - `⚠️ 部分实现`：数据结构、服务或测试存在，但不是默认路径，或只实现了子集
> - `❌ 未实现`：当前代码库中没有可运行实现

---

## 1. 总体结论

当前仓库已经实现了一个相当完整的本地优先记忆/检索底座，以及一套可运行的认知编排骨架，但旧版对应表有两类明显失真：

1. 把已经支持的能力写成“未实现”
2. 把仅存在于底层服务、测试或可选路径中的能力写成“默认已落地”

本次审计后的结论是：

- 词法优先检索、taxonomy 分类、DSL 摘要落盘、工作记忆装配、价值投影、元认知门控已实现；`embedding_only` / `hybrid` 的检索代码路径已实现，且 remote embedding（OpenAI 兼容 /embeddings）+ sqlite-vec KNN 地基已接通（不可用时降级 JSON 扫描）
- 反刍、世界模型快照、自我模型快照、技能模板 runtime read-model 等能力已实现为库层/服务层能力；agent-search 默认路径已自动进入反刍闭环，长周期候选走 `ruminate` 维护入口
- 行动执行器、真正的世界状态演化接口、图关系层、完整的默认认知学习闭环，仍是部分实现或未实现

## 3. 关键纠偏

### 3.1 记忆分类并非“未实现”

旧说法：

- “未实现分类器，DSL 仍由 LLM 生成”

当前事实：

- `src/memory/classifier.rs` 已实现 `KeywordTaxonomyClassifier`
- `src/memory/pipeline.rs` 的 `DefaultMemoryPipeline::default_v1()` 使用 `KeywordTaxonomyClassifier + RuleBasedSummaryGenerator`
- `tests/memory_classifier.rs`、`tests/memory_pipeline_default.rs` 已覆盖分类输出
- `src/ingest/mod.rs` 的默认 ingest 路径优先走 rule-based summary；只有在配置了 LLM 且 summary backend 选择 Rig 时，才进入 Rig summary 路径

审计结论：

- `✅ taxonomy 分类器已实现`
- `✅ 默认 DSL 摘要并不依赖 LLM`
- `⚠️ Rig summary 是可选增强路径，不是唯一实现`

### 3.2 双通道检索并非“保留未实现”

旧说法常把 `embedding_only` / `hybrid` 说成“Phase 1 保留”。

当前事实：

- `src/search/mod.rs` 已实现 `RetrievalMode::LexicalOnly / EmbeddingOnly / Hybrid`
- `embedding_recall()`、候选合并、通道 trace、降级逻辑都已存在
- `tests/dual_channel_retrieval.rs`、`tests/retrieval_cli.rs`、`tests/agent_search.rs` 已覆盖双通道检索与 agent-search 复用
- 本次同步修正了 `src/core/app.rs`、`src/core/status.rs`、`src/core/doctor.rs` 中的 readiness/gating 语义，使其和真实运行前置条件一致，不再把缺失 `vector.backend` 的配置误报为 ready

2026-11 embedding 地基落地后的新增事实：

- **远程 embedding 通道已接通**：`src/memory/embedding.rs` 的 `RemoteHttpEmbeddingGenerator` 针对 OpenAI 兼容 `POST {base_url}/embeddings`（参考部署：硅基流动 `BAAI/bge-m3`），配置为 `[embedding] backend="remote_http"`。批量上限 32 条/请求（超量自动分批）、瞬时失败重试 2 次线性退避（4xx 鉴权/参数错误快速失败）、首条向量维度一致性 + 配置 `dimensions` 校验、默认 30s 超时。key 只从配置或环境变量 `AGENT_MEMOS_EMBEDDING_API_KEY` 读取
- **vector backend sqlite_vec 已接通**：`src/memory/vector.rs` 通过 sqlite-vec 静态扩展在 `Database::open` 注册 vec0 模块；`record_embeddings`（JSON）保持事实源，写入时双写进 `vector.table` 指定的 vec0 虚表（懒创建、cosine 距离），检索时 `embedding_recall` 优先走原生 KNN（backend+model 过滤 + k 余量），扩展缺失/维度不匹配/索引丢失时自动退回 JSON 余弦扫描——召回正确性不依赖索引存活。`MemoryRepository::backfill_vector_index` 供存量行补索引（`ruminate` 维护入口内建调用）
- **hybrid 默认可用**：`ingest` 全部落向量（remote_http 批量、builtin 离线、openai rig 逐条）→ lexical+embedding 合并去重 → 语义近邻召回，端到端不依赖 LLM。`tests/remote_embedding_http.rs`（本地 mock HTTP 服务）与 `tests/vector_sqlite.rs` 覆盖分批/重试/维度校验/vec0 往返/降级/端到端

审计结论：

- `✅ embedding_only / hybrid 检索代码已实现`
- `✅ 远程 embedding 生成与 sqlite-vec KNN 通道已接通（含降级路径）`
- `✅ agent-search 已复用普通检索模式`

### 3.3 认知闭环不能一概写成“默认已完成”

当前事实：

- `src/agent/orchestration.rs` 同时有 `execute()` 与 `cycle()`
- `cycle()` 才会构造 rumination trigger、调度队列、drain short-cycle
- 反刍服务 `src/cognition/rumination.rs`、治理桥接、候选落盘、短周期写回都已经实现并有测试

2026-11 反刍闭环落地后的新增事实：

- **默认 agent-search 已自动进闭环**：`[cognition] auto_rumination`（默认 `true`）下，CLI `agent-search` 走 `cycle()`——报告产出后自动 enqueue 对应触发（Warning→session_boundary/LPQ；veto→metacog_veto/SPQ），并 drain 一条在队短周期项写回 local adaptations；CLI 侧装配器换用 `AdaptiveSelfStateProvider`，写回结果在下次 agent-search 的工作记忆 self_state 中可见（闭环）。JSON 模式 stdout 报告契约不变，反刍摘要走 stderr
- **长周期入口已留好**：`agent-memos ruminate` CLI 子命令 + 库函数 `cognition::rumination::run_maintenance_pass`（短/长队列各 drain 上限 64 条、单队列出错即停该队列、附带 vector 索引 backfill），daemon 夜间调度可直接调用
- `tests/rumination_auto_cycle.rs`、`tests/ruminate_cli.rs` 覆盖上述行为

审计结论：

- `✅ 认知循环骨架已实现`
- `✅ agent-search 默认路径自动进入反刍闭环（可配置关闭）`

## 6. 默认运行路径 vs 可选能力

### 默认更可信的能力

- `ingest` 会把记录落库，并为每条记录生成 taxonomy + DSL sidecar
- `search` 会执行 lexical / embedding / hybrid 检索，并保留 citation / trace
- `agent-search` 会执行检索、工作记忆装配、价值投影、元认知门控，并输出结构化报告

### 需要条件或额外接线的能力

- `embedding_only` / `hybrid` 需要 embedding backend（builtin / openai / remote_http）、model 与 `vector.backend=sqlite_vec` 就绪；远程 backend 额外需要可达的 `api_base` 与 key。sqlite-vec 扩展不可用时自动降级为 JSON 余弦扫描（召回不变，仅延迟上升）
- 自我模型/技能模板/世界模型的 runtime persisted read-model 依赖 `subject_ref` 和相关持久化状态
- 长周期反刍候选（promotion/skill/value）依赖显式调用 `ruminate` / `run_maintenance_pass`（daemon 夜间调度）

## 7. 仍然存在的主要差距

| 差距 | 状态 | 备注 |
|---|---|---|
| 世界模型作为长期动态模型的使用深度不够 | ⚠️ | 现在更像可选快照/预测层，而不是默认主导层 |
| 默认 agent-search 仍偏“决策支持报告” | ⚠️ | 行动选择有了，但真实执行链薄 |
| 反刍不是所有默认命令的自动后处理 | ✅（agent-search） | agent-search 默认闭环；ingest/search 命令不反刍（语义上无报告可喂） |
| embedding 双通道运行前置条件 | ✅ | remote_http + sqlite_vec 地基落地；降级路径明确 |
| 图关系/跨主题关联层缺失 | ❌ | 仍以树状主路径为主 |
